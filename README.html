Deploy to Vercel

The repo is a static site and is ready for Vercel as it stands. There is no build step: data/data.js is committed, so Vercel serves the files directly.

  1. In Vercel, choose Add New → Project and import orangejam72/loops.
  2. Leave Framework Preset as Other, and leave the build and output settings empty.
  3. Deploy. Every push to the production branch redeploys, and every other branch gets a preview URL.
  4. Under Settings → Deployment Protection, turn on Vercel Authentication (or password protection) so only invited people can open it.

Or from a terminal: npx vercel for a preview, npx vercel --prod for production.

# routes on the deployed site
/          dashboard
/prd       product requirements
/readme    this page

What the config does:

  • vercel.json adds clean URLs, the /prd and /readme routes, noindex and basic security headers, and no caching on data/, so a new report appears straight after deploy.
  • .vercelignore keeps source/ (the raw email with contact details) and scripts/ off the deployed site. They stay in the repo.
  • robots.txt asks search engines not to crawl the site.

Add a new daily report

  1. Save the latest email from Outlook as .eml into source/.
  2. Add a record to days in data/daily_reports.json with the figures from its “Loop Testing Status” table. Update systems, constraints and milestones if they changed.
  3. Run the build. It uses only the Python standard library: 
    python3 scripts/build_data.py
  4. Reload index.html. KPIs, deltas, charts and findings all recalculate from the data.
  5. Commit and push. Vercel redeploys automatically.

Reading the numbers

  • CPCL: commissioning check list. CWA: the completions system where CPCLs are recorded.
  • OK / PB / OS: accepted, accepted with Punch B, outstanding.
  • Each data point is dated by the day it describes. The email goes out the next morning.
  • The “Data notes” section of the dashboard lists definition changes and figures in the source emails that do not reconcile.

Handling

The source email contains names and contact details of project staff from several companies. Keep the repository private. The deployed site leaves out the raw email, but the dashboard still names companies, systems and tags, so keep Deployment Protection on and agree who may see it before sharing more widely.
