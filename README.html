Loops

A dashboard for Norfolk Vanguard ICT loop testing. It turns the daily “Loop test daily Look Ahead” email thread into one page of KPIs, trends, system status, constraints and the planned loop lists. It works in light and dark mode, exports to PDF and a single offline web page, and is hosted on Vercel behind a login with a share link for guests.

View it locally

Open index.html in a browser. It needs no server and no build.

Light and dark mode

Every page has an Auto / Light / Dark switch in the top bar. Auto follows the device setting; Light and Dark pin the choice, which the browser remembers for next time. Charts redraw in the matching colours. Printing and the PDF always use the light theme.

Exports

  • PDF (exports/loops-dashboard.pdf): A4 landscape, light theme, about seven pages. The loop register is summarised rather than listed in full. The PDF button on the dashboard downloads it; Print gives the same layout from the browser.
  • Offline page (exports/loops-dashboard-offline.html): one HTML file with the data, fonts and scripts embedded. It opens from email, Teams or a USB stick with no internet connection, and keeps the charts, tooltips, theme switch and searchable register.

Both are generated, so rebuild them whenever the data changes (see Add a new daily report).

Deploy to Vercel

Live at loops-blue.vercel.app (Vercel project loops). The repo is a static site with no build step: data/data.js and exports/ are committed, so Vercel serves the files directly. To set it up again from scratch:

  1. In Vercel, choose Add New → Project and import orangejam72/loops.
  2. Leave Framework Preset as Other, and leave the build and output settings empty.
  3. Deploy. Every push to the production branch redeploys, and every other branch gets a preview URL.
  4. Under Settings → Deployment Protection, set Vercel Authentication to All Deployments. It is set this way now, so only people logged in to Vercel with access to the team can open the site.

Or from a terminal: npx vercel for a preview, npx vercel --prod for production.

Share link

To let someone without a Vercel login see the site, send them the share link. It is the site address with a secret added:

https://loops-blue.vercel.app/?x-vercel-protection-bypass=SECRET&x-vercel-set-bypass-cookie=true
  • The first visit sets a cookie, so the rest of the site (PDF, offline page, PRD) works for that browser afterwards.
  • Anyone holding the link can view the site, so share it only with the people on the distribution list.
  • The secret is never stored in this repo. Find it, or revoke it and make a new one, in Vercel under Settings → Deployment Protection → Protection Bypass for Automation. Revoking it stops the old link working straight away.
  • For someone who should not get a lasting link, use the deployment's Share button in Vercel instead; that link expires after 23 hours.

What the config does:

  • vercel.json adds clean URLs, the /prd and /readme routes (rewrites must point at the clean path, e.g. /docs/PRD, not /docs/PRD.html), noindex and basic security headers, and no caching on data/, so a new report appears straight after deploy.
  • .vercelignore keeps source/ (the raw email with contact details) and scripts/ off the deployed site. They stay in the repo.
  • robots.txt asks search engines not to crawl the site.

Add a new daily report

  1. Save the latest email from Outlook as .eml into source/.
  2. Add a record to days in data/daily_reports.json with the figures from its “Loop Testing Status” table. Update systems, constraints and milestones if they changed.
  3. Run the build. It uses only the Python standard library: 
    python3 scripts/build_data.py
  4. Rebuild the PDF and offline page, then run the checks. These need Node and Playwright (npm install -g playwright@1.56.1 once): 
    NODE_PATH="$(npm root -g)" node scripts/build_exports.cjs
NODE_PATH="$(npm root -g)" node scripts/test_dashboard.cjs
  5. Reload index.html. KPIs, deltas, charts and findings all recalculate from the data.
  6. Update this README and the PRD change log if anything beyond the data changed, then commit and push. Vercel redeploys automatically.

Testing

scripts/test_dashboard.cjs opens every page in headless Chromium and checks: KPIs match the latest data, charts draw, no script errors, no sideways scroll on a phone, the theme switch works and is remembered on all three pages, the offline page makes no network requests and still renders everything, and the PDF is valid, current and between 3 and 10 pages. It exits with an error if any check fails.

Reading the numbers

  • CPCL: commissioning check list. CWA: the completions system where CPCLs are recorded.
  • OK / PB / OS: accepted, accepted with Punch B, outstanding.
  • Each data point is dated by the day it describes. The email goes out the next morning.
  • The “Data notes” section of the dashboard lists definition changes and figures in the source emails that do not reconcile.

Handling

The source email contains names and contact details of project staff from several companies. Keep the repository private. The deployed site leaves out the raw email, but the dashboard still names companies, systems and tags, so keep Deployment Protection on and agree who may see it before sharing more widely.
